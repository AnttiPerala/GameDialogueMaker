# Game Dialogue Maker — GDevelop playground

The downloadable apple-quest demo: talk to Mira, close the conversation, touch
the red apple with green leaves, then return to Mira. Pickup removes the apple
and sets numeric `hasApple = 1`; Mira's root conditions select the request at
`hasApple = 0` and the thank-you at `hasApple = 1`. Returning before pickup still
shows the request. Restart Play/Preview to reset. The pickup is enabled only
when the source demo's `demoAppleQuest` flag is true.

1. Extract the ZIP to a local folder, keeping assets/ beside game.json.
2. In the current GDevelop 5 desktop editor, open game.json.
3. Click Preview. Move with WASD or arrows and touch an NPC to talk.
4. Click choices, scroll long text, and close with Escape or the close button.
   Leave the NPC and return to restart its dialogue.

The scene contains a native Sprite player, an NPC Sprite and Text label for every
character, and a following camera for larger casts. Instances are visible and
editable in GDevelop's scene editor. The simple white PNG is tinted at runtime.
Native GDevelop sprite collision masks detect contact; NPCs are not obstacles.
Movement pauses while dialogue or test variables are open.

A JavaScript event in the scene drives movement and dialogue. Its accessible
HTML overlay has scrollable text, choice buttons, and test-variable controls.
It supports newline pages, questions, answer branches, Next jumps, conditions,
empty characters, and simulated fight outcomes. All conditions on a link must
pass; normal nodes follow the first allowed link. Next is used only if there are
no outgoing links. Variables start at zero (numbers) or empty text (strings).
Both desktop preview and normal web exports have the DOM required by the UI.
Touch/gamepad movement and multiplayer are not implemented.

Dialogue is stored as JSON in the GDMDialogue scene variable, and original editor
data is included in dialogue-source.json. Editing that standalone JSON alone does
not update the game. Re-export after editing in Dialogue Maker, or update the
scene variable directly. User text is rendered as textContent, never HTML/code.
Names are data, so duplicate names and punctuation do not affect object IDs.

For integration, runtimeScene.__gdmDialogue.variables contains mutable condition
values; call runtimeScene.__gdmDialogue.render() while a conversation is active
after changing those values externally. Scene unload removes UI and listeners;
scene pause/resume hides and restores the overlay. Keep the Player and NPC_N
object names when replacing their artwork. Add ordinary GDevelop events around
the included JavaScript event to extend the game.

The base project was generated by GDevelop's official libGD.js 5.6.283 core.
No extensions, external services, or extra code files need to be installed to
use this export. All game assets are local. The GDevelop editor itself may need
its normal network access. Use desktop open for the ZIP's relative asset paths.

Validation covers resource references, embedded event syntax, dialogue logic,
and core-library project deserialization when LIBGD_JS is supplied. A browser
harness tests movement/contact and DOM controls with simulated engine APIs.
These checks do not establish a successful graphical GDevelop Preview run.

Engine smoke test: Preview, move to both NPCs, advance dialogue pages, choose
each branch, try win/loss, set keys to 1 to unlock the gate, close, leave/re-enter,
and test the empty character. Also verify long text, many choices, and scene
pause/resume/unload when integrating the scene into another game.
